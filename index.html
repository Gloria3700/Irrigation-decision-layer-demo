PUBLIC IRRIGATION CONTEXT

Why collective irrigation is a useful pilot for a decision-layer PhD

Public descriptions of the Authion setting show collective allocation, many withdrawal points, annual allocation planning, changing crop-water demand and drought constraints. The research demonstrator does not reproduce a real partner rule; it uses this public context to make the RP logic concrete.

~600irrigating farms in the public Authion description
16–18k hairrigated annually
23–30 Mm³annual irrigation withdrawals reported publicly

10management units in the collective allocation framework
A3Pcrop demand + hydrology + AI + satellite information
Existing management context

Allocation, monitoring and operational constraints already exist

The scientific problem is therefore not to invent water management from scratch. A real pilot already has actors, allocation rules, constraints, monitoring practices and recurring decision points that must first be reconstructed and formalised.

Research gap

Prediction does not specify action

A probability, ensemble or scenario set becomes operational only after it is interpreted within a decision context. The RP therefore separates decision context, predictive information and decision strategy before asking what action should follow.

    WP B · CONTROLLED INFORMATION EXPERIMENT

    Keep the state, feasible actions and decision rule fixed. Change only the forecast information.

    This isolates the contribution of information. The experiment asks whether a different representation changes the action, its timing or intensity, and then whether the changed action improves an outcome.

    FIXED state + feasible actions + simple decision rule → CHANGED forecast information → compare action + outcome

    WP C · STRATEGY COMPARISON + COMPLEXITY TEST

    Keep state and forecast fixed. Change the way uncertainty is turned into action.

    The action is an output, not a fixed input. A more complex strategy only clears the first RP gate when it changes the action and improves a partner-relevant outcome. Stability, interpretability, data needs and maintenance burden are then considered before further testing.

    FIXED state + forecast → CHANGED decision strategy → compare action + partner-relevant outcome + operational burden
    Illustrative chance-constrained strategy

    Use a partner-agreed violation tolerance

    The rule selects the least restrictive feasible action whose synthetic violation probability is below the chosen tolerance. In a real pilot, the tolerance would be agreed with operational partners.
